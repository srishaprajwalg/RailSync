# RailSync

**Automatic Block Planning System**

**SIH Problem Statement:** AI-Powered Automatic Block Planning to Maximize Asset Availability for Train Operations on Indian Railways.

## 1. Project Overview & Prototype Scope

RailSync is a prototype decision-support system designed to automate and optimize railway maintenance block planning. By transitioning from decentralized, manual maintenance scheduling (where Engineering, Signalling, and Traction departments request independent blocks) to an algorithmic approach, RailSync consolidates multi-department tasks and schedules them into existing timetable "white spaces," maximizing asset uptime.

**Simulation Corridor:** Bengaluru City (SBC) → Jolarpettai (JTJ) (~140 km, Double/Multiple Line).

> **Important Disclaimer:** Corridor, timetable, and maintenance data are entirely simulated/approximate and are **not** actual Indian Railways operational data. The metrics generated by this prototype (such as a 55% downtime reduction) are the results of a simulated scenario and do not represent validated real-world performance claims.

## 2. Implemented Architecture

The prototype is currently implemented end-to-end with the following stack and components:

### Backend (Python/FastAPI)
- **FastAPI API**: Exposes the simulation data and optimization engine.
- **Pydantic**: Enforces strict schemas for `Station`, `TrainSchedule`, `MaintenanceTask`, and `PlannedBlock`.
- **Timetable Analyzer**: Extracts train occupancies from schedules and identifies safe "white spaces" with required margins.
- **Compatibility Matrix**: Explicitly models resource and safety constraints between different task types (e.g., Track Tamping vs. Point Overhaul) to ensure safe consolidation.
- **Optimization Engine**: Uses **Google OR-Tools (CP-SAT Solver)** as the primary optimizer for coordinated block planning. It evaluates safety margins, timetable gaps, departmental compatibility, and task deadlines to assign multi-department tasks to consolidated blocks. A heuristic fallback is planned for edge cases.

### Frontend (React/Vite)
- **Dashboard**: A React-based interface utilizing Tailwind CSS v4, providing a professional railway operations dashboard.
- **KPICards**: Displays real-time simulation metrics, including requested tasks, successfully planned tasks, and simulated downtime reduction.
- **CorridorTimeline**: A custom SVG Time-Distance graph that plots train movements alongside scheduled maintenance blocks.
- **BlockPlan**: Lists the generated, consolidated multi-department blocks.
- **TaskTable**: A comprehensive view of all incoming maintenance requests and their current planning status.

## 3. End-to-End Workflow

1. The frontend fetches the mock corridor definitions, simulated 24-hour train timetables, and randomly generated maintenance requests (from TMS, SMMS, TDMS).
2. The user clicks "Generate Optimal Plan".
3. The frontend calls `POST /api/optimize`.
4. The CP-SAT engine analyzes the constraints, identifies contiguous white spaces, applies the compatibility matrix, and packs compatible tasks into single consolidated blocks.
5. The API returns the optimized blocks.
6. The dashboard updates to visualize the Time-Distance graph, block details, and downtime reduction metrics.

## 4. API Endpoints

- `GET /api/corridor`: Returns simulated stations and chainages.
- `GET /api/timetables`: Returns simulated train schedules (Up/Down lines).
- `GET /api/tasks`: Returns synthetic multi-department maintenance tasks.
- `POST /api/optimize`: Runs the CP-SAT optimizer and returns generated blocks and metrics.
- `GET /api/blocks`: Returns the currently planned blocks.

## 5. Current Capabilities & Limitations

**Capabilities:**
- Successfully models and enforces task compatibility constraints.
- Identifies timetable white spaces and schedules tasks without train overlaps.
- Demonstrates multi-department task consolidation in a single block.

**Limitations:**
- **Simulated Data**: All inputs are mock data; they lack real-world Indian Railways complexity.
- **Global White-Space Analysis**: The timetable analyzer currently extracts global white spaces across the entire line direction, rather than performing granular, block-section by block-section analysis.
- **Uniform-Speed Abstraction**: The Time-Distance visualization draws straight lines between station arrivals and departures, abstracting away realistic train physics and curvature.
- **Unvalidated Results**: The prototype results (including the ~55% block time reduction observed in testing) are purely theoretical and operationally unvalidated.

## 6. Setup and Run Instructions

### Backend Setup

```bash
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt # (or pip install fastapi uvicorn ortools pandas pydantic)
uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

### Frontend Setup

```bash
cd frontend
npm install
npm run dev
```

The frontend will be available at `http://localhost:3000` (or the port specified by Vite), and the backend runs on `http://127.0.0.1:8000`.
